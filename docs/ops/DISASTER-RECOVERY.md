## 1. ماذا يُنسَخ وماذا لا يُنسَخ

| الأصل | النسخ | ملاحظة |
|---|---|---|
| قاعدة Turso (البيانات + `schema_migrations`) | نسخة Turso المُدارة (يومية مستهدفة) | تحقّق من جدول النسخ في اللوحة وسجّله في §4 |
| البذرة (12 منتجًا + الأسئلة) | في المستودع (`src/lib/seed`) — نسخة الكود هي النسخة | تكفي للقراءة الطارئة فقط |
| متغيرات البيئة والأسرار | **ليست في المستودع أبدًا** — في مدير أسرار المالك | فقدها = إعادة إصدار كل الرموز (§3 من `secret-rotation.md`) |
| تقارير المجسّ JSON | قطع أثرية 90 يومًا | أثر التدقيق، ليست نسخة بيانات |

## 2. الاستعادة (على قاعدة خدش أولًا — دائمًا)

1. أنشئ قاعدة **جديدة فارغة** للاختبار (لا تستعِد فوق الإنتاج مباشرةً أبدًا).
2. نفّذ الاستعادة إليها من اللوحة.
   > **مالك-ليؤكّد:** خطوات النسخ/الاستعادة الدقيقة (لوحة Turso الحالية) — تُؤخَذ
   > من [توثيق Turso](https://docs.turso.tech) وقت التنفيذ. هذا الملف لا يخترع
   > أوامر CLI ولا أزرار لوحة.
3. **شاهد السلامة:** وجّه المجسّ للقاعدة المستعادة — يجب أن يُظهر `db-identity`
   نسب الإنتاج **بنفس البصمة** (`fp …`) و`mig-parity` أخضر. أي بصمة مختلفة =
   استعادة مرفوضة (قاعدة خطأ أو نسخة قديمة).
4. تحقق من عيّنة بيانات (عدّ `products`/`orders` وقارن بالمتوقع تقريبًا).
5. بدّل رابط الإنتاج عبر `apply-turso-secrets.sh` + `vercel deploy --prod`.
6. `FINAL: PASS` على الإنتاج + smoke أخضر = إغلاق الحادث (§2 من الـ runbook).

## 3. سيناريوهات جاهزة

- **حذف/فساد بيانات جزئي:** استعادة خدش ← استخراج الصفوف السليمة ← إدخالها عبر
  مسارات الكتابة الطبيعية (لا SQL يدويًا على الإنتاج).
- **فقد القاعدة كليًا:** استعادة خدش ← تحقق البصمة ← تبديل الرابط (§2).
- **فقد الأسرار فقط:** ليست كارثة بيانات — تدوير كامل (§3 من `secret-rotation.md`).
- **انقطاع Turso الإقليمي:** لا إجراء بنيويًا — البذرة تغطي القراءة، والكتابة
  `503` مُعلَن حتى عودة المزوّد (يُتابَع عبر قضية `turso-probe`).
