# المرحلة الخامسة: مزود Vercel AI Gateway (اختياري)

هذه الوثيقة هي عقد إضافة مزود AI Gateway إلى سلسلة التراجع: ما أُضيف، وما لم يتغيّر، وكيف يُتحقّق منه، وكيف يُعكس.

**المبدأ الحاكم:** أي قدرة جديدة تُضاف **خلف علم الميزة المستقل القائم** (`ENABLE_AI_AGENT`)، وتكون **اختيارية بحكم التكوين** (غياب المفتاح = غياب المزود)، ولا تغيّر أي مسار قائم عند الإغلاق.

---

## 1) ما أُضيف

| العنصر | الملف | الوصف |
|---|---|---|
| مزود AI Gateway | `src/lib/ai/providers/ai-gateway.ts` | واجهة متوافقة مع OpenAI على `https://ai-gateway.vercel.sh/v1`؛ مفتاح `AI_GATEWAY_API_KEY`، موديل `AI_GATEWAY_MODEL` بشكل `creator/model` |
| موضعه في السلسلة | `src/lib/ai/chain-order.ts` | **آخر** السلسلة قبل الرد المحلي — لا يُطلب إلا بعد سقوط Gemini/Groq/NIM |
| تسجيله في المحرك | `src/lib/ai/agent-engine.ts` | مدخل واحد في `pools`؛ لا تغيير في أي منطق تسلسل أو أدوات |
| حجب مفاتيح Vercel | `src/lib/errors/index.ts` | نمط `v(ck|cp|ci|ca|cr)_…` ⇒ `[REDACTED_VERCEL_KEY]` |
| اختبارات الحراسة | `tests/ai-gateway.test.ts` | سياسة الرابط والموديل، العقد، حجب المفتاح، وموضعه في السلسلة |

> **لا اعتمادية خارجية جديدة.** هذه المرحلة **لا** تضيف حزمة `ai` (Vercel AI SDK) ولا `@ai-sdk/gateway`: البوابة OpenAI المتوافقة تُنادى بنفس العميل الموحّد الذي يخدم Groq وNIM (`src/lib/ai/tools/openai-compatible.ts`). سبب الاختيار: المستودع يبني مزوديه يدويًا بلا SDK، وإضافة الحزمة الآن تُدخل طبقة كاملة (بث، أدوات، موردون) لا يحتاجها مسار النص الحالي.

---

## 2) الأعلام والمتغيرات

| المتغير | القيمة | الافتراضي | الحدود المفروضة |
|---|---|---|---|
| `ENABLE_AI_AGENT` | `true` لتشغيل المحرك النمطي | معطّل | من المرحلة الأولى — لم يتغيّر |
| `AI_GATEWAY_API_KEY` | مفتاح AI Gateway (بادئته `vck_`) | غائب ⇒ المزود غير متاح ويُتخطّى | — |
| `AI_GATEWAY_MODEL` | اسم الموديل على البوابة | `openai/gpt-5.5` | **شكل `creator/model` حصرًا**؛ أي قيمة بلا `/` ⇒ المزود غير متاح |
| `AI_GATEWAY_BASE_URL` | لتوجيه المزود لمٌحاكي محلي في الاختبارات | `https://ai-gateway.vercel.sh/v1` | **https فقط**؛ أي مخطط آخر ⇒ المزود غير متاح |

## 3) السلسلة بعد المرحلة الخامسة

```
ENABLE_AI_AGENT != "true"  ⇒  رد محلي فوري (بدون شبكة)

ENABLE_AI_AGENT = "true"   ⇒  Gemini ← Groq ← NVIDIA NIM ← AI Gateway ← الرد المحلي
                                                                    │
                                                                    └─ عند ENABLE_MCP_TOOLS = true **و** طلب الأدوات:
                                                                       دورة أدوات محدودة عبر McpToolRegistry
```

**لماذا في الآخر لا في الأول:** بهذا لا يتغيّر أي سلوك قائم حين تعمل Gemini أو Groq أو NIM — البوابة لا تُنادى إلا بعد سقوط كل ما قبلها. لمن يريدها أولى (موديل أقوى، مفتاح واحد لكل المزوّدين):

```bash
AI_PROVIDER_ORDER=ai-gateway
```

`resolveProviderOrder` تضمن أن `local` يبقى في النهاية مهما حدث، وأن الأسماء غير المعروفة تُتجاهل بلا ترقية ضمنية.

---

## 4) بوابات المزود (fail-closed بالترتيب)

1. **المفتاح** — غياب `AI_GATEWAY_API_KEY` ⇒ `isAvailable() = false` ⇒ تُخطّيه السلسلة صامتًا.
2. **الرابط** — `AI_GATEWAY_BASE_URL` يجب أن يبدأ بـ `https://`؛ غير ذلك ⇒ غير متاح (لا يمرّ مفتاح على قناة غير مشفّرة).
3. **اسم الموديل** — يجب أن يحمل شكل `creator/model`؛ البوابة ترفض `gpt-5.5` المجرد برسالة لا تذكر السبب، فالحكم محلي وصريح.
4. **النداء** — أي خطأ نقل أو HTTP غير 2xx يمرّ عبر `redactSecrets` (`vck_…` ⇒ `[REDACTED_VERCEL_KEY]`) ثم يُرمى للأعلى فتنتقل السلسلة للمزود التالي.

لا نداء شبكة يُطلق أبدًا عندما تكون التهيئة فاسدة (اختبار يثبت ذلك).

---

## 5) ضمانات أمنية

- **https إلزامي** للرابط المخصّص — نفس سياسة NIM.
- **حجب المفتاح قبل الطباعة:** نمط مفاتيح Vercel المسبوقة مضافة إلى `redactSecrets`. الاعتماد على نمط `Bearer` وحده غير كافٍ، لأن البوابة قد تُعيد المفتاح داخل **جسم** الخطأ.
- **صفر سطح جديد:** لا مسار HTTP، لا زر، لا واجهة — المزود مدخل في سلسلة قائمة فقط.
- **المقاييس:** فشل المزود يُسجّل عبر `metrics.recordAiFailure("ai-gateway")` باسمه، فلا يُخلط مع بقية المزوّدين.

## 6) صفر كسر — مصفوفة السلوك

| `ENABLE_AI_AGENT` | `AI_GATEWAY_API_KEY` | بقية المفاتيح | السلوك |
|---|---|---|---|
| غائب/`false` | أي قيمة | أي قيمة | رد محلي فوري — مطابق لما قبل المرحلة الخامسة حرفيًا |
| `true` | غائب | Gemini/Groq/NIM متاح | نفس المسار القديم حرفيًا؛ البوابة لا تُنادى |
| `true` | موجود | Gemini/Groq/NIM متاح | نفس المسار القديم حرفيًا (البوابة في آخر السلسلة) |
| `true` | موجود | الكل بلا مفاتيح | الرد المحلي — لا 500 للمستخدم |
| `true` | موجود | الكل فشل/فارغ | البوابة تُنادى، وإن فشلت ⇒ الرد المحلي |
| `true` | موجود، رابط `http://` | أي قيمة | البوابة غير متاحة (fail-closed) ⇒ ما بعدها |

## 8) التراجع (Rollback)

العكس إعداد لا كود:

- احذف `AI_GATEWAY_API_KEY` (أو اجعله فارغًا) ⇒ يخرج المزود من السلسلة تلقائيًا لأن `isAvailable()` تعتمد على وجود المفتاح.
- أو اضبط `AI_PROVIDER_ORDER` بلا `ai-gateway`.

لا هجرات، لا تغيير في المخطط، لا تغيير في عقود API، ولا بيانات يُعاد إنشاؤها.

---

## 9) الفرق بين مفاتيح Vercel — فخٌّ يستحق التوثيق

ثلاثة أنواع تُخلط بينها بسهولة، وأولها فقط يصلح لهذه المرحلة:

| البادئة | ما هو | مصدره | يصلح لـ |
|---|---|---|---|
| `vck_…` | **AI Gateway API key** | AI Gateway → API Keys | ✅ مزود هذه المرحلة |
| `vcp_…` | **رمز منصة** (Access Token) | Account Settings → Tokens | النشر عبر CLI/API، وأسرار GitHub (`VERCEL_TOKEN`) |
| — | توكن `vercel login` (OAuth) | `~/.vercel` أو `com.vercel.cli` | أوامر CLI من جهازك فقط — قصير العمر، **لا** يصلح سرًّا دائمًا |

الخلط بين `vck_` و`vcp_` هو ما أوقف نشرات متتالية في هذا المستودع: كلاهما يبدو «رمز Vercel»، وكلاهما يفشل في مكان الآخر برسالة لا تذكر السبب. نمط الحجب في `redactSecrets` يغطي العائلة كاملة (`vck_`, `vcp_`, `vci_`, `vca_`, `vcr_`).
