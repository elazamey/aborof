# تشغيل أسطول الوكلاء — النشر التدريجي، المراقبة، وحالة لوحة الإدارة

المرجع: [`phase-4-agent-fleet.md`](./phase-4-agent-fleet.md) (المعمارية) و[`agent-manifest-template.md`](./agent-manifest-template.md) (قالب وكيل).

## 1) النشر التدريجي الفعلي (بلا وعود مستحيلة)

| المرحلة | كيف تُنفَّذ فعليًا على هذا المستودع | الحالة |
|---|---|---|
| **Canary** | نشر معاينة (Preview) من فرع غير `main` مع `ENABLE_AGENT_FLEET=true` — بيئة Vercel للمعاينة منفصلة بمتغيراتها، وهي قناة الـ Canary الطبيعية هنا | ✅ جاهزة: أي PR ينتج معاينة تلقائيًا (تكامل Git فعّال) |
| **Staging** | مشروع Vercel منفصل يشير إلى نفس المستودع مع متغيرات بيئة خاصة | ✅ ممكن (يوجد فعلًا أكثر من مشروع على المستودع) |
| **Gradual Production 10% → 50% → 100%** | ❌ **غير ممكن كما هو مطلوب** | Vercel لا يوزّع نسبة مئوية من الزيارات بين نسختين. النسبة تحتاج طبقة توزيع (Edge Middleware مع Flag / مزود Feature Flags خارجي) — قرار بنية لا يكفي فيه علم البيئة |
| **Rollback فوري** | `ENABLE_AGENT_FLEET=false` (أو حذف المتغير) على مشروع الإنتاج + إعادة نشر | ✅ بلا أي تغيير كود |

> **الخلاصة بصراحة:** لكل تطبيق احتمالان فقط — النسخة القديمة أو الجديدة. «الـ 10%» تُنال بتقسيم **شرائح** لا زيارات: مثلًا تفعيل الأسطول على قناة الدعم أو محادثات الأقسام اللوجستية أولًا عبر توجيه الأعمال، أو استخدام مزود Feature Flags (GrowthBook/Unleash) عند الحاجة الجدية.

## 2) المراقبة — ما هو موجود فعلًا وما يحتاج ربطًا

| البند المطلوب | الحالة في المستودع |
|---|---|
| معدل التوجيه الصحيح | ✅ سجل `fleet_routing` يحمل `primary` + `matched_terms` — القياس يحتاج تجميعًا على Vercel Logs (Log Drain) |
| زمن الاستجابة | ✅ `metrics.recordTiming` للمزودين + زمن الأداة في `mcp_tool_call` |
| معدل الأخطاء | ✅ سلسلة تراجع صامتة + `metrics.recordAiFailure` لكل مزود فاشل |
| نسبة استخدام الأدوات / عدد الاستدعاءات لكل وكيل | ✅ المطابقة ممكنة بدمج سجلي `fleet_routing` (الوكيل) و`mcp_tool_call` (الأداة) عبر نفس الطلب |
| سجل قرار التوجيه | ✅ سطر JSON واحد لكل قرار: `primary`, `supporters`, `routed_by`, `confidence`, `low_confidence`, `matched_terms`, `allowed_tools`, `message_chars` — **وبلا نص رسالة العميل** |
| تنبيهات تجاوز الزمن/الأخطاء | ⚠️ خارج نطاق الكود: تُضبط في منصة الاستضافة (Log Drains + تنبيه) على الحقول أعلاه |

### نموذج سطر السجل

```json
{"level":"info","event":"fleet_routing","primary":"logistics_shipping_cost","primary_department":"logistics",
 "supporters":[],"routed_by":"keyword","confidence":1,"low_confidence":false,
 "matched_terms":["الشحن كام","شحن"],"matched_count":2,
 "allowed_tools":["shipping_estimate","store_info"],"message_chars":19}
```

**الحجب مقصود:** لا نص رسالة، ولا هاتف، ولا رقم طلب. كل الحقول من عندنا (معرّفات وكلاء + محفزات الكتالوج + درجات) ⇒ السجل قابل للتجميع والتنبيه بلا أي مخاطرة خصوصية.

### قرار تصميمي: لا جدول توجيهات في قاعدة البيانات

كتابة قرار توجيه لكل رسالة تعني كتابة على Turso مع **كل** محادثة، وتخزين ما يقترب من محتوى العميل — أي كلفة ومسؤولية خصوصية بلا مقابل تشغيلي حقيقي. السجل المهيكل في منصة الاستضافة يكفي للمراقبة والتنبيه، ويبقى قليلًا وسهل الحجب عند الحاجة.

## 3) لوحة الإدارة — العقد الحالي (كل شيء للعرض فقط)

### `GET /api/admin/agents`

| الحالة | الاستجابة |
|---|---|
| `ENABLE_AGENT_FLEET != "true"` | `404` موحّد (`NOT_FOUND`) لا يكشف وجود النقطة |
| العلم مفعّل بلا جلسة إدارة | `401` (`AUTH_REQUIRED`) |
| العلم مفعّل مع جلسة | `200` مع اللقطة والمانيفست |

```json
{
  "ok": true,
  "enabled": true, "active": true,
  "size": 50, "declared_size": 50, "effective_size": 49,
  "disabled_agents": ["ops_stock_alerts"], "disabled_all_specialists": false,
  "read_only_tools": ["lookup_faq","search_products","shipping_estimate","store_info"],
  "departments": [{"department":"sales","count":10}, "…"],
  "agents": [
    {"id":"sales_floor_care","name":"خبير منظفات الأرضيات","department":"sales",
     "mission":"…","keywords":9,"tools":["search_products","lookup_faq"],
     "escalate_to_human":false,"is_default":false,"disabled":false},
    "…50 عنصرًا"
  ]
}
```

**لماذا لا يوجد مفتاح تبديل حقيقي داخل اللوحة:** النشر على Vercel يوزّع الطلب على نسخ متعددة؛ أي حالة قابلة للتغيير في ذاكرة العملية ستجعل بعض النسخ تعطّل وكيلًا وبعضها لا — أي قرار غير متسق لا يمكن الوثوق به في حادثة. لذلك التعطيل **بيئي تصريحي** (`FLEET_DISABLED_AGENTS`) ويُقرأ من كل النسخ بالتساوي، والثمن إعادة نشر.

### إجراء الطوارئ (fail-closed) بالترتيب

```bash
# 1) ألطف إجراء: أوقف المتخصصين وأبقِ الافتراضي (الشخصية باقية، التخصص مختفٍ)
vercel env add FLEET_DISABLED_AGENTS production     # القيمة: *
vercel deploy --prod

# 2) إيقاف الأسطول كليًا والعودة للسلوك السابق حرفيًا
vercel env rm ENABLE_AGENT_FLEET production
vercel deploy --prod

# 3) إيقاف المحرك النمطي نفسه (يشمل الأسطول وكل مزود)
vercel env rm ENABLE_AI_AGENT production
vercel deploy --prod
```

## 4) حدود معلنة (ما لم يُبنَ ولماذا)

| الطلب | القرار | السبب |
|---|---|---|
| توزيع 10% / 50% / 100% | **لم يُبنَ** | يحتاج طبقة تعيين خارج Vercel — نطاق بنية لا كود |
| Distributed tracing كامل | **لم يُبنَ** | لا مزود APM مربوط في المستودع؛ السجل المهيكل الحالي أساس جاهز له متى رُبط |
| حد معدل لكل وكيل | **لم يُبنَ** | لا نموذج تهديد يبرره: الكلفة محدودة بـ(طول المحادثة × سقف استدعاءات MCP=≤8)، وحد الدردشة 30/10د لكل IP قائم. إضافة 50 عدّادًا تعقيد بلا مقابل |
| مفتاح تبديل لحظي في اللوحة | **لم يُبنَ** (استُبدل بالتعطيل البيئي + `*`) | حالة غير متسقة بين نسخ serverless — انظر أعلاه |
| A/B Testing على شرائح | **لم يُبنَ** | يحتاج تعريف شرائح وتعيين ثابت لكل زائر ومقياس تحويل — مشروع قياس مستقل |
| اختبار حمل 10x حقيقي | **مُصغَّر مقصود** | يوجد سقف زمني على 5000 قرار توجيه (رصد انحدار داخلي)؛ الحمل الشبكي الحقيقي يحتاج بيئة اختبار مستقلة |
