# المرحلة الرابعة — أسطول وكلاء المتجر (50 وكيلًا)

المرجع: [`phase-2-nim-mcp.md`](./phase-2-nim-mcp.md) (طبقة الأدوات المحكومة) و[`phase-3-ux-roadmap.md`](./phase-3-ux-roadmap.md) (تتبع الطلبات وتجربة العميل).

## الفكرة في سطر

خمسون وكيلًا **تصريحيًا** يخدمون المتجر، يختار بينهم موجّه حتمي (بلا موديل وبلا شبكة)، وكل وكيل يرى **مجموعة فرعية** من أدوات MCP المسجّلة للقراءة فقط — بلا أي مسار تنفيذ جديد وبلا قدرة كتابة، والنظام كله معطّل افتراضيًا.

## لماذا تعريفات لا مسارات

| لو بنيناها كـ 50 مسارًا/وحدة | ما بنيناه فعلًا |
|---|---|
| 50 نقطة HTTP جديدة = 50 سطحًا للهجوم | صفر مسار تنفيذ جديد: التنفيذ ما زال حصريًا في `McpToolRegistry` |
| 50 نسخة من منطق الأدوات والحدود | حد واحد مركزي (سقف الاستدعاءات/المهلة/اقتصاص المخرجات) يفرضه السجل |
| احتمال كتابة بيانات بالخطأ | كل أدوات الأسطول `readOnly` — والتحقق البنائي يرفض أي غير ذلك |
| صعوبة مراجعة السلوك | كتالوج بيانات + محقق بنائي + 26 اختبارًا تحرس العقود |

## التدفق

```text
POST /api/chat
  └─ ENABLE_AI_AGENT != "true" ⇒ المسار القديم حرفيًا (بلا أي حقل جديد)
  └─ ENABLE_AI_AGENT == "true"
       └─ ENABLE_AGENT_FLEET != "true" ⇒ المحرك كما كان (سلوك المرحلة الثانية)
       └─ ENABLE_AGENT_FLEET == "true"
            ├─ selectAgents(آخر رسالة)  ← نقاط نصية حتمية، بلا موديل
            ├─ تقييد الأدوات = أدوات الوكيل ∩ المسجّل للقراءة فقط
            ├─ إضافة قسم الوكيل إلى رسالة النظام (سقف 1200 حرف)
            └─ الاستجابة تحمل `fleet` مع هوية الوكيل وسبب الاختيار
```

## الأنماط الثلاثة المحكومة

1. **حتمية التوجيه:** نفس المدخل ⇒ نفس المخرج دائمًا (بلا عشوائية ولا تعلّم)، ويعمل بلا أي مفتاح مزوّد — لأن الرد المحلي هو الحالة الافتراضية في الإنتاج.
2. **تقاطع لا اتحاد:** قائمة أدوات الوكيل تُضرب في `READ_ONLY_TOOL_NAMES` عند التسجيل، وفي `listTools()` المرئية عند التنفيذ. فلا يمكن لتعريف وكيل أن يمنح أداة غير مسموحة، ولا أن يوسّع ما تسمح به `MCP_ALLOWED_TOOLS`.
3. **ميزانية ثابتة:** قسم الأسطول لا يتجاوز `FLEET_PROMPT_BUDGET` حرفًا مهما طالت التعريفات، فلا يتضخم الطلب المرسل للموديل.

## الأعلام (fail-closed، كلها اختيارية)

| المتغير | الأثر | الافتراضي |
|---|---|---|
| `ENABLE_AGENT_FLEET` | `true` **مع** `ENABLE_AI_AGENT=true` ⇒ توجيه الأسطول + حقل `fleet` في الاستجابة + نقطة المانيفست | مغلق |
| `ENABLE_AI_AGENT` | شرط سابق للأسطول: الأسطول لا يعمل فوق المسار القديم | مغلق |
| `ENABLE_MCP_TOOLS` | يُبقي حصر الأدوات فعّالًا؛ بدونها يعمل الأسطول نصيًا بلا أدوات | مغلق |

> أي قيمة غير `true` (بما فيها `TRUE` أو `1`) تُبقي الميزة مغلقة — وهذا مُختبَر.

## الصلاحيات المعروضة للإدارة

`GET /api/admin/agents` — مانيفست للعرض فقط:

- `404` موحّد عندما يكون العلم مغلقًا (لا يكشف وجود النقطة)، بنفس مبدأ `/api/admin/mcp/tools`.
- `401` بلا جلسة إدارة.
- مع الجلسة: العدد، الأقسام، الأدوات المسموحة عالميًا، وقائمة الوكلاء (المعرّف/الاسم/القسم/المهمة/الأدوات/التصعيد).
- **لا يوجد أي مسار HTTP لتنفيذ وكيل أو أداة**: التنفيذ داخل دورة المحرك وحدها.

## التشغيل والتراجع

```bash
# تشغيل (Vercel → Production ثم إعادة نشر)
vercel env add ENABLE_AI_AGENT   production   # true (إن لم يكن مفعّلًا)
vercel env add ENABLE_AGENT_FLEET production  # true
# عند الحاجة لطبقة الأدوات المحكومة مع الأسطول:
vercel env add ENABLE_MCP_TOOLS  production   # true

# التراجع الفوري: احذف العلم أو اضبطه على أي قيمة غير true
vercel env rm ENABLE_AGENT_FLEET production
```

التراجع **بلا نشر كود** وبلا أثر جانبي: تعطيل العلم يعيد السلوك السابق حرفيًا (لا `fleet` في الاستجابة، لا توجيه، لا حصر أدوات).

## ما يجب ألا يحدث (محمي باختبارات)

- إضافة وكيل بأداة غير مسجّلة أو كاتبة ⇒ يفشل التحقق البنائي واختبارات الأسطول.
- توسيع عدد المحفزات/طول المهمة خارج الحدود ⇒ نفس المصير (وقد أوقف هذا الفحص ثلاث مخالفات فعلية أثناء التطوير).
- ظهور حقل `fleet` بلا تفعيل العلم ⇒ يكسر اختبار عقد `/api/chat`.
- تجاوز ميزانية رسالة النظام ⇒ يكسر اختبار الميزانية.
- ظهور أي سر في المانيفست أو رسالة النظام ⇒ يكسر اختبار الحجب.
