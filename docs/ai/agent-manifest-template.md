# قالب تعريف وكيل — انسخه والصقه

ملف المرجع: `src/lib/ai/agents/catalog/<department>.ts` (الأقسام: `sales` · `support` · `logistics` · `payments` · `operations`).

## القالب الأدنى الصالح

```ts
{
  id: "sales_carpet_care",                 // snake_case لاتيني، 3-40 حرفًا، يبدأ بحرف، فريد
  name: "خبير تنظيف السجاد والموكيت",        // ≤ 60 حرفًا — يظهر للعميل
  department: "sales",                     // من AGENT_DEPARTMENTS فقط
  mission: "رشّحي حلول تنظيف السجاد والموكيت بحسب نوع الألياف ومستوى البقع.",  // 15-180 حرفًا
  keywords: [                              // 3-10 محفزات، كل واحد ≤ 40 حرفًا بعد التطبيع
    "سجاد", "موكيت", "تنظيف السجاد", "بقع السجاد",
  ],
  tools: ["search_products", "lookup_faq"], // من الأدوات المسجّلة للقراءة فقط — إلزاميًا غير فارغة
  guidance: [                              // 1-3 قواعد، كل واحدة ≤ 160 حرفًا
    "اسألي عن نوع الألياف قبل ترشيح المنظف.",
    "نبّهي أن التجربة على بقعة صغيرة أولًا تقي من تغيّر اللون.",
  ],
  escalateToHuman: true,                   // اختياري: يطلب التصعيد للواتساب في نهاية الرد
}
```

## القواعد الملزمة (يفرضها المحقق البنائي + بوابات CI)

| القاعدة | العقوبة عند المخالفة |
|---|---|
| أدوات من `READ_ONLY_TOOL_NAMES` فقط | `npm run security:gates` يفشل في CI (لا ملاحظة مراجعة) |
| لا استيراد `@/lib/db` أو `@/lib/orders` أو `@/lib/auth` داخل الكتالوج | نفس البوابة تفشل — الكتالوج بيانات لا سلوك |
| `readOnly: false` ممنوع تمامًا | البوابة تفشل |
| العدد الكلي يبقى 50 وكل قسم 10 | `tests/agent-fleet.test.ts` يفشل |
| وكيل افتراضي واحد بالضبط (`isDefault`) | نفس الاختبار |
| معرّف فريد بصيغة `snake_case` | `validateFleet()` يستبعد المخالف ويطبع تحذيرًا |

## بعد الإضافة — تحقق محليًا

```bash
npm run security:gates                     # الأدوات والاستيرادات
node --import tsx --test tests/agent-fleet.test.ts
npm test                                   # المجموعة الكاملة
```

## أضف اختبارًا للتوجيه (إلزامي عمليًا)

في `tests/agent-fleet.test.ts` → قسم «الرسائل المتخصصة تُوجَّه لوكيلها الصحيح» أضف سطرًا:

```ts
["عايز منظف سجاد", "sales_carpet_care"],
```

> لماذا إلزامي: بلا هذا السطر قد تفوز عبارة وكيل آخر على محفزاتك عند التعادل، ولن يعرف أحد حتى يشتكي عميل. الاختبار هو عقد التوجيه.

## أوزان التوجيه (لمعايرة المحفزات)

| الحالة | الدرجة |
|---|---|
| عبارة متعددة الكلمات مطابقة كاملة | `2 + عدد كلماتها` |
| كلمة مفردة = رمز مطابق تمامًا | `1.5` |
| كلمة مفردة (≥ 5 أحرف) واردة داخل المدخل | `1` |
| كلمة من **اسم** الوكيل | `0.75` |

عند **تساوي الدرجة تمامًا**: تُحسم بالأقسام بترتيب `FLEET_DEPARTMENT_PRIORITY` (المبيعات ← اللوجستيات ← الدفع ← الدعم ← التشغيل)، ثم بترتيب الكتالوج. لا تُقدَّم درجة أدنى على أعلى أبدًا.

## تعطيل وكيل بلا كود

```bash
# في Vercel → Production ثم إعادة نشر
FLEET_DISABLED_AGENTS="sales_carpet_care,ops_stock_alerts"   # تعطيل محدَّد
FLEET_DISABLED_AGENTS="*"                                    # كل المتخصصين ⇒ الافتراضي وحده
```

- الوكيل المعطَّل يبقى موسومًا `disabled: true` في المانيفست الإداري (عرض لا حذف).
- الوكيل الافتراضي **لا يُعطَّل أبدًا** — يبقى للتوجيه مخرج دائم.
- إن كان الوكيل المعطَّل هو المتخصص الوحيد لموضوع ما، يسقط ذلك الموضوع للوكيل العام بأمان (`routed_by: "fallback"`) بدل تخمين وكيل غير معني.
