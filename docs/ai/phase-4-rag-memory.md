# المرحلة الرابعة: ذاكرة المتجر (RAG) — استرجاع نصي بلا مفاتيح

**القرار المنفَّذ:** نبدأ بالاسترجاع النصي المباشر (Keyword match بسلوك FTS-like) بلا أي مفتاح،
ثم نضيف المتجهات (embeddings) تدريجيًا خلف **نفس العقد** بلا تغيير أي كود في التطبيق.

---

## 1) لماذا نصي أولًا

| السبب | الأثر |
|---|---|
| بلا مفاتيح وبلا حصة استهلاك | يعمل الآن على Turso أو بكتالوج البذرة، وبلا كلفة وبلا حدود أسبوعية |
| حتمي بالكامل | نفس الاستعلام = نفس الترتيب، فالاختبارات والقياس قابلان للتكرار |
| بلا تغيير في المخطط | لا هجرة ولا جدول جديد ولا فهرسة مطلوبة في هذه المرحلة |
| يفهم العامية المصرية | التطبيع + المرادفات يغطيان «مطهر/ديتول/كلوركس»، «الشحن كام»، «حاجة للتعقيم» |
| أساس للقياس | نقيس hit@3 وزمن الاستجابة اليوم، فتصير إضافة المتجهات مقارنة موثّقة لا انطباعًا |

## 2) البنية والعقد

```
src/lib/ai/memory/
├── types.ts              عقد MemoryEngine + MemoryDocument + MemoryHit + الحدود
├── policy.ts             الحدود المركزية والأعلام (لا يستطيع أي محرك توسيعها)
├── normalize.ts          تطبيع عربي + كلمات توقف + تقشير خفيف + فهرس مرادفات
├── corpus.ts             بناء الذاكرة من المنتجات + الأسئلة الشائعة + بيانات المتجر
├── engines/keyword.ts     المحرك النصي (الافتراضي، متاح دائمًا)
├── engines/embeddings.ts  محرك المتجهات — عقد مكتمل يعلن نفسه غير متاح بعد
└── index.ts              الواجهة العامة: searchKnowledge() + resolveMemoryEngine()
```

```ts
export interface MemoryEngine {
  readonly name: string;
  readonly kind: "keyword" | "vector" | "remote";
  isAvailable(): boolean;
  search(
    documents: readonly MemoryDocument[],
    query: MemoryQuery,
    limits: MemoryLimits
  ): Promise<MemoryHit[]>;
}
```

الواجهة **غير متزامنة عن قصد**: المحرك النصي يجيب فورًا، ومحرك المتجهات مستقبلًا يحتاج نداء شبكة —
والعقد نفسه يستوعبه بلا تغيير في أي مستدعٍ.

**الاستخدام الوحيد من خارج الوحدة:**

```ts
const result = await searchKnowledge("عايز حاجة للتعقيم", { topK: 3 });
// ⇒ { engine: "keyword", hit_count: 2, corpus_size: 27, hits: [...] }
```

## 3) كيف يعمل المحرك النصي

1. **تطبيع:** إزالة التشكيل والتطويل، توحيد `أإآٱ→ا` و`ى→ي` و`ة→ه` و`ؤ→و`، تحويل الأرقام العربية-الهندية، إزالة الترقيم.
2. **تقشير خفيف:** إزالة «ال» التعريف وبعض اللواحق فقط عندما يبقى 3 أحرف على الأقل (حتى لا تُتلف الكلمات القصيرة).
3. **كلمات توقف:** «عايز/من/فضلك/كام؟» ← تُستبعد، فلا تشوّش الترتيب.
4. **توسيع بالمرادفات:** 19 مجموعة مرادفات مصرية (مطهر/معقم/ديتول/كلوركس · أرضيات/سيراميك/رخام · شحن/توصيل/دليفري…)، والمصطلح القادم من المرادفات يُرجَّح بوزن أقل (×0.55) فلا يسبق نص المستخدم الصريح.
5. **ترتيب BM25 مبسّط:** وزن الحقل (عنوان 3.2 · كلمات مفتاحية 2.4 · نص 1.0) × ندرة المصطلح (IDF) + مكافأة تغطية كل المصطلحات + مكافأة مطابقة العنوان الكاملة.
6. **حد أدنى للدرجة:** استعلام غير ذي صلة يُعيد **صفر نتائج** بدل تخمين — والأداة تقول للموديل ذلك صراحةً.

الذاكرة مخبّأة 30 ثانية (`getKnowledgeBase`) مع `invalidateKnowledgeBase()` لإبطال فوري عند أي تعديل في الكتالوج من لوحة الإدارة.

## 4) الأعلام والحدود

| المتغير | القيمة | الافتراضي | الحدود المفروضة |
|---|---|---|---|
| `ENABLE_RAG` | `true` لتفعيل الذاكرة وأداة `search_knowledge` | **معطّل** | غيابه ⇒ صفر استرجاع وصفر عمل وصفر أدوات مرئية |
| `RAG_ENGINE` | `keyword` \| `embeddings` \| `remote` | `keyword` | قيمة غير معلنة أو محرك غير متاح ⇒ سقوط آمن للنصي |
| `RAG_TOP_K` | عدد النتائج | `3` | 1–5 |
| `RAG_MIN_SCORE` | الحد الأدنى للدرجة | `2` | 1–50 |
| `RAG_MAX_DOCUMENTS` | سقف ما يُمسح من الذاكرة | `600` | 50–2000 |

**بوابة مزدوجة:** أداة `search_knowledge` تحتاج `ENABLE_MCP_TOOLS=true` **و** `ENABLE_RAG=true` معًا.
الفحص يقع عند كل نداء لا عند التسجيل، فأي تغيير في العلم يسري فورًا.

## 5) الأدوات المحكومة بعد هذه المرحلة

| الأداة | المصدر | البوابات |
|---|---|---|
| `search_products` | الكتالوج | الطبقة + السماح + الحدود |
| `lookup_faq` | الأسئلة الشائعة | الطبقة + السماح + الحدود |
| `shipping_estimate` | جدول المحافظات | الطبقة + السماح + الحدود |
| `store_info` | بيانات المتجر | الطبقة + السماح + الحدود |
| **`search_knowledge`** | **ذاكرة المتجر (جديد)** | الطبقة + **`ENABLE_RAG`** + السماح + الحدود |

نتائج `search_knowledge` عن المنتجات تُعاد بنفس عقد `search_products` (`structuredContent`) —
لذلك تظهر كبطاقات منتجات بزر «أضف للسلة» في المحادثة **بلا أي كود إضافي في الواجهة**.

---

## 6) الخصوصية والحدود الأمنية

- الذاكرة تحتوي: المنتجات + الأسئلة الشائعة + بيانات المتجر. **لا تحتوي أي بيانات عميل** (لا طلبات، لا هواتف، لا عناوين)، واختبار صريح يفحص ذلك.
- حقول `metadata` المسموح تمريرها للواجهة محدودة بقائمة مغلقة (id/name/price/old_price/category/image/stock/phone/whatsapp).
- الأداة **قراءة فقط**، وتحتاج بوابة `search_knowledge` المرئية؛ وأدوات الكتابة تبقى مرفوضة في التسجيل إلا ببوابة مستقلة.
- كل استدعاء يمر بنفس تدقيق MCP: مقياس + سطر سجل بلا وسائط ولا مخرجات ولا أسرار.

## 7) خطة الترقية التدريجية (بلا تغيير في العقد)

### أ) FTS5 على Turso (بديل/مدعّم للمحرك النصي)
1. فحص قدرة: التحقق أن بناء libsql/Turso الحالي يدعم `fts5` قبل أي هجرة.
2. هجرة مُرقّمة: إنشاء جدول افتراضي `memory_fts(product_id, name, body)` + مشغّلات مزامنة مع جدول `products`.
3. محرك `turso-fts5` يحقق `MemoryEngine` نفسه ويُختار بـ `RAG_ENGINE=turso-fts5`.
4. أي فشل في الفحص أو الاستعلام ⇒ سقوط تلقائي للمحرك النصي الحالي (لا تعطيل للخدمة).

### ب) المتجهات (embeddings)
1. تضمين المستندات مرة واحدة عبر مزود موجود أصلًا (Gemini أو NVIDIA NIM) وحفظ المتجهات في Turso بهجرة مُرقّمة.
2. تضمين الاستعلام عند كل بحث + ترتيب بالتشابه الجيبي.
3. **ترتيب هجين:** النصي للدقة الحرفية + المتجهات للمرادفات البعيدة، بوزن صريح يُضبط بالقياس.
4. تشغيل ملف `engines/embeddings.ts` الموجود (يعلن `isAvailable() === false` حتى ذلك الحين).

### ج) خدمة استرجاع خارجية (اختياري)
نفس الأداة يمكن أن تنادي خدمة استرجاع متوافقة (NeMo Retriever أو غيرها) عبر `RAG_SERVICE_URL` **https فقط** —
العقد ثابت والمصدر قابل للتبديل.

## 8) القياس (نمط `rag-eval`)

| المؤشر | كيف يُقاس | الحالة |
|---|---|---|
| hit@3 | مجموعة أسئلة متجر (مرادفات + أسماء منتجات + أسئلة سياسات) ← هل الإجابة الصحيحة ضمن أول 3؟ | مجموعة أولية داخل `tests/memory.test.ts` |
| Recall@3 للمرادفات | استعلامات لا تحمل الاسم الحرفي («حاجة للتعقيم») | ✅ يمر |
| الدقة (عدم التخمين) | استعلام غير ذي صلة يجب أن يُعيد صفر نتائج | ✅ يمر |
| الزمن p50/p95 | `recordMcpToolCall` يقيس زمن كل استدعاء أداة في المقاييس | يُقرأ من `/api/admin/diagnostics` |

الهدف المعلن للترقية إلى المتجهات: ألا تقل hit@3 عن النصي الحالي، مع بقاء المهلة المركزية 4 ثوانٍ.

## 10) التراجع

إعداد لا كود: احذف `ENABLE_RAG` (أو اجعله `false`) وأعد النشر ⇒ تختفي الأداة من قائمة الأدوات،
ويعود `searchKnowledge` بنتيجة فارغة بلا أي عمل، ولا يتغير أي سلوك آخر. لا هجرات ولا بيانات تُعاد.
