# قاموس حقول تعريف الوكيل + المانيفست المحمول

المرجع التنفيذي: `src/lib/ai/agents/types.ts` (المصدر الوحيد للحقيقة) · المخرجات المولَّدة: `docs/ai/agents.manifest.json` و`agents.manifest.yaml`.

## 1) لماذا TypeScript مصدرًا وJSON/YAML مخرَجًا مولَّدًا

| الاعتبار | كتالوج TypeScript (المختار) | ملف JSON/YAML يُحرَّر يدويًا |
|---|---|---|
| انحراف المصادر | مستحيل: مصدر واحد | مؤكد مع الوقت (نسختان لتعريف واحد) |
| سلامة الأنواع | `tsc` يرفض الخطأ قبل التشغيل | لا شيء — خطأ صامت حتى الإنتاج |
| التحقق البنائي | عند التحميل **وفي** التفاعل المباشر | يحتاج طبقة تحميل جديدة |
| تعديل غير المخوَّلين | عبر PR ومراجعة | ملف قابل للتعديل بلا مراجعة مسار الكود |
| الاستهلاك الخارجي | ✅ عبر مولِّد (JSON + YAML) | ✅ مباشر |

**القرار:** البيانات تُكتب في الكتالوج، ويُولَّد المانيفست المحمول بـ`npm run agents:export`؛ ولا يُحرَّر الملف المولَّد يدويًا أبدًا — وفحص CI (`npm run agents:check`) يُفشل أي انحراف بين الملف والكود.

## 2) قاموس الحقول

| الحقل | النوع | إلزامي | القيد | يقابله في الصيغة المقترحة |
|---|---|---|---|---|
| `id` | string | ✅ | `snake_case` لاتيني، 3-40 حرفًا، يبدأ بحرف، فريد | `agent_id` |
| `name` | string | ✅ | ≤ 60 حرفًا — يظهر للعميل | `display_name` |
| `department` | enum | ✅ | `sales` \| `support` \| `logistics` \| `payments` \| `operations` | `domains` (مبسَّط إلى قسم واحد مسؤول) |
| `mission` | string | ✅ | 15-180 حرفًا — جملة أمر واحدة | `description_ar` |
| `keywords` | string[] | ✅ | 3-10 عناصر، كل عنصر ≤ 40 حرفًا بعد التطبيع | `trigger_keywords` |
| `tools` | string[] | ✅ | غير فارغة، وكل أداة من `READ_ONLY_TOOL_NAMES` | `allowedTools` (أسماء الأدوات الحقيقية: `search_products`, `lookup_faq`, `shipping_estimate`, `store_info`) |
| `guidance` | string[] | ✅ | 1-3 عناصر، كل عنصر ≤ 160 حرفًا | (جزء من `system_prompt_ar`) |
| `examples` | `{input, expected}[]` | ✅ | 2-4 لكل وكيل، `expected` = `id` صاحبه، والسلوك مُختبَر آليًا | `examples` ✅ مُعتمَد |
| `escalateToHuman` | boolean | ➖ | إن صحّ، يُطلب ذكر الواتساب في نهاية الرد | `fail_closed_behavior` (جزئيًا) |
| `isDefault` | boolean | ➖ | وكيل واحد بالضبط في الأسطول، ولا يُعطَّل أبدًا | `priority` (يُعامل كحالة خاصة) |

## 3) حقول مقترحة **لم تُعتمد** — والبديل المعتمد

| الحقل المقترح | القرار | السبب والبديل |
|---|---|---|
| `system_prompt_ar` لكل وكيل | ❌ | رسالة النظام **تُركَّب** من `mission` + `guidance` في `prompt.ts` تحت ميزانية `FLEET_PROMPT_BUDGET` (1200 حرف). نص حر لكل وكيل = رسائل غير مراجَعة تتضخم بلا سقف، وتكرار لما هو مُختبَر. |
| `priority` لكل وكيل | ❌ (عام) | الأولوية **بين الأقسام** لا بين الوكلاء: `FLEET_DEPARTMENT_PRIORITY`. أولوية رقمية لكل وكيل تجعل الكتالوج هشًّا (رقم واحد يقلب قرارات لا يقصدها أحد)، والترتيب الرقمي الحالي يُحسم بترتيب الكتالوج المقروء. |
| `confidence_threshold` لكل وكيل | ❌ (عام) | `LOW_CONFIDENCE_THRESHOLD` عام (0.5) ويُوسَم في السجل. عتبة لكل وكيل تعني 50 سياسة تُدار — والوسم للمراجعة يحل الغرض بلا هشاشة. |
| `read_only_tools_only` | ✅ مُعتمَد **كقيد مُفروض** لا كحقل | لا يمكن أن يكون `false` من الأصل: البوابة الثابتة ترفض أي أداة كاتبة، والتحقق البنائي كذلك. |
| `rate_limit` لكل وكيل | ❌ | الحدود قائمة على المحاور الصحيحة: 30/10د لكل IP على `/api/chat`، وسقف استدعاءات MCP ≤ 8 لكل رسالة. حد لكل وكيل يضيف 50 عدّادًا بلا نموذج تهديد. |
| `admin_only` | ❌ | يُستبدل بالقسم: وكلاء `operations` عرضهم الإداري فقط، والمانيفست كله خلف `401` + جلسة إدارة. العلم المنفصل يزيد احتمال الخطأ. |
| `domains` (متعدد) | ❌ | قسم واحد مسؤول لكل وكيل: تعدد الانتماء يخلق تعارضًا في الحسم والمراقبة بلا مقابل. |

## 4) المانيفست المحمول — الشكل الفعلي

```json
{
  "generated_by": "مُولَّد آليًا — لا تُحرَّر يدويًا: npm run agents:export",
  "format_version": 1,
  "fleet": { "size": 50, "effective_size": 50, "disabled_agents": [], "read_only_tools": ["…"] },
  "mcp_policy": { "enabled": false, "write_tools_allowed": false, "max_calls_per_request": 3, "…": "…" },
  "agents": [
    {
      "id": "logistics_shipping_cost",
      "name": "مسؤول تكلفة الشحن",
      "department": "logistics",
      "mission": "احسبي تكلفة الشحن للمحافظة ومجموع السلة واذكري حد الشحن المجاني.",

      "escalate_to_human": false,

        { "input": "الشحن كام؟", "expected": "logistics_shipping_cost" },

      ]
    }
  ]
}
```

## 5) دورة حياة الإضافة (خمس خطوات)

```bash
# 1) أضف الوكيل في ملف القسم مع كل الحقول الإجبارية (بينها examples 2-4)
# 2) حدّث العدد المتوقع في AGENT_FLEET_SIZE إن تغيّر
npm test                                  # المحقق + الأمثلة المولَّدة من كل الوكلاء
npm run security:gates                    # أداة كاتبة؟ استيراد db؟ ⇒ فشل فوري
npm run agents:export                     # ولّد JSON + YAML
npm run agents:check                      # اطمئن أن لا انحراف (نفس ما يفعله CI)
```

## 6) حدود معلنة

- `examples` تُختبَر مقابل **التوجيه** فقط، لا مقابل جودة الرد النهائي من الموديل (ذلك يحتاج تقييمًا بنماذج حقيقية — خارج نطاق CI بلا مفاتيح).
- المانيفست يصف الحالة بالبيئة التي وُلِّد فيها (`enabled: false` في التطوير مثلًا)؛ لا يعكس حالة الإنتاج الحيّة. الحالة الحيّة تُقرأ من `GET /api/admin/agents` بجلسة إدارة.
