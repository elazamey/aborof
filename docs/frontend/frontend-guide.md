# الواجهة الأمامية — النوع الحالي وخطة التطوير

قياس مباشر من المستودع (آخر تحديث: 2026-09-28، الفرع `arena/01a0e69c-aborof`).

## 1) نوع الواجهة: Next.js App Router خام بلا أي مكتبة واجهة

| الطبقة | المستخدم فعليًا | ملاحظة |
|---|---|---|
| الإطار | **Next.js 16.3.5** (App Router) | Server Components افتراضيًا |
| مكتبة العرض | **React 18** + TypeScript (`strict`) | بلا مكتبة مكونات (لا shadcn/MUI/Chakra) |
| التنسيق | **CSS عادي** في `globals.css` (322 سطرًا) | متغيرات CSS + كلاسات مركّبة — **بلا Tailwind، بلا CSS-in-JS** |
| الحركة/الأيقونات | إيموجي و CSS transitions | بلا مكتبة أيقونات أو Framer Motion |
| إدارة حالة السلة | `localStorage` + حدث `cart-updated` + حدث `storage` للتزامن بين التبويبات | بلا Redux/Zustand/Context — لا حاجة فعلية |
| جلب البيانات | Server Components تستدعي `@/lib/db` مباشرة | الصفحات `force-dynamic` |
| الاعتماديات كليًا | 5 إنتاجية فقط (`next`, `react`, `react-dom`, `@libsql/client`, `zod`) | سطح تبعيات ضئيل مقصود |

**توزيع المكونات:** 7 ملفات عميلة (`Header`, `ProductGrid`, `ChatWidget`, `cart`, `admin`, `AddButton`, `lib/cart`) والباقي خادمي. الصفحات: `/` و`/cart` و`/product/[id]` و`/admin`.

**الوصف في سطر:** واجهة RTL مصرية بسيطة، خفيفة جدًا (الحزمة الثابتة ~693 كيلوبايت)، تُبنى بـJSX + CSS متغيرات، وتُخدَم من Server Components — أي **«Next.js خام»** لا «Next.js + منظومة واجهة».

## 2) القيود المعمارية التي تحكم أي تطوير (ليست تفضيلات — بعضها مُفروض ببوابات)

1. **CSP مضبوط ويحدّ ما يمكن إضافته** (`src/lib/security/headers.ts`):
   - `font-src 'self' data:` ⇒ **خطوط Google ممنوعة** بلا تعديل السياسة؛ الخطوط تُستضاف محليًا أو تُعدَّل السياسة مع تبرير.
   - `script-src 'self' 'unsafe-inline'` ⇒ لا سكربتات طرف ثالث (تحليلات، جلسات تسجيل) بلا إضافتها للسياسة ورفع `CSP_ENFORCE`.
   - `connect-src 'self' + Gemini/Groq/Vercel` ⇒ أي API خارجي جديد (تتبع، دفع، SMS) يحتاج تعديل السياسة.
   - `img-src 'self' data: https:` ⇒ صور المنتجات يمكن أن تُستضاف محليًا أو من نطاق https.
2. **عزل العميل/الخادم مفروض ببوابة CI**: مكوّن `"use client"` لا يجوز أن يستورد `@/lib/auth|secrets|db|orders|rate-limit` — الفحص يفشل البناء (`npm run security:gates`).
3. **`npm audit --audit-level=high` يحجب النشر** ⇒ أي مكتبة واجهة جديدة تدخل عبر بوابة تدقيق، لا بحرية.
4. **`npm run security:bundle`** يفحص الحزمة بعد البناء: لا أسماء ولا قيم أسرار — يمنع تمرير بيانات خادمية إلى مكوّن عميل.
5. **لا اختبارات DOM/E2E** حاليًا: كل الـ198 اختبارًا خادمية/منطقية. أي تطوير واجهة **بلا شبكة أمان آلية** اليوم.

## 3) الفجوات المرصودة (بالدليل، لا بالرأي)

| الفجوة | الدليل | الأثر |
|---|---|---|
| لا صور حقيقية للمنتجات | لا يوجد أي `<img>` أو `next/image` في المشروع؛ `image` حقل إيموجي | فقدان ثقة ومعدل تحويل في متجر حقيقي |
| لا حدود أخطاء/تحميل | `loading.tsx` · `error.tsx` · `not-found.tsx` · `global-error.tsx` **كلها غائبة** | فشل قاعدة البيانات = صفحة بيضاء/خطأ خام للعميل |
| SEO غير مكتمل | لا `sitemap.ts` · `robots.ts` · `opengraph-image` · ولا `generateMetadata` لصفحة المنتج | منتجات غير قابلة للفهرسة ولا للمشاركة ببطاقة |
| لا PWA/manifest | لا `manifest.ts` | لا «أضف للشاشة الرئيسية» — مهم لمتجر يعتمد واتساب |
| JSX مضغوط في سطور طويلة | `ProductGrid.tsx` (29 سطرًا) و`ChatWidget.tsx` (300 سطر) بسطور من مئات الأحرف | صعوبة المراجعة والتعديل الآمن |
| `force-dynamic` على الصفحة الرئيسية | `page.tsx` يقرأ القاعدة في كل زيارة | لا كاش للكتالوج — كلفة وزمن استجابة أعلى |
| لا قياس أداء أمامي | لا Web Vitals ولا ميزانية أداء في CI | لا يُكتشف انحدار الأداء إلا بشكوى |
| صور/خطوط بلا تحسين | `globals.css` بلا `@font-face`، ولا تحسين صور | مفقود عند إضافة صور حقيقية |

## 4) خطة التطوير — أربع مراحل مرتّبة بالأثر

### المرحلة 1: صمود الوجه (2–4 ساعات، بلا أي اعتمادية جديدة) — **أعلى أثر/أقل مخاطرة**
- `src/app/loading.tsx` + `error.tsx` + `not-found.tsx` + `global-error.tsx` بأسلوب الموقع نفسه.
- `generateMetadata` لصفحة المنتج (اسم المنتج + الوصف + صورة المشاركة) — أكبر مكسب SEO بلا مكتبات.
- `sitemap.ts` و`robots.ts` (ديناميكيان من نفس مصدر المنتجات).
- `manifest.ts` (PWA أساسي: اسم، أيقونة، `theme_color`, `display: standalone`).
- **معيار القبول:** `npm run build` ينجح، والصفحات الأربع تظهر بلا HTML تقني مكشوف.

### المرحلة 2: التحويل (بيع أكثر بنفس الواجهة)
- **صور حقيقية للمنتجات**: حقل `image` يقبل مسارًا محليًا `/products/p1.webp` مع `next/image` (متوافق مع `img-src 'self'`) والاحتفاظ بالإيموجي كبديل.
- شريط تقدّم «الشحن المجاني» في صفحة السلة (باقي كم جنيه للشحن المجاني — الحساب موجود في `@/lib/shipping`).
- زر «اطلب واتساب» ثابت للموبايل (sticky) أسفل الشاشة.
- تحقق فوري في نموذج الطلب (هاتف مصري، محافظة، عنوان) بأخطاء عربية واضحة قبل الإرسال.
- إظهار «تبقّى 3 قطع» عند المخزون المنخفض + حالة «نفذت الكمية» موجودة أصلًا.
- **معيار القبول:** لا تغيير في شكل استجابة `/api/chat` أو `/api/orders`، وبقاء بوابة عزل العميل/الخادم خضراء.

### المرحلة 3: جودة آلية (تحتاج قرارًا منك: إضافة تبعية تطوير)
- **اختبارات مكوّنات** بـ`node:test` + `jsdom` (وأفضل: `@testing-library/react`) — تغطية: السلة (إضافة/حذف/كمية)، الفلترة والترتيب، `ChatWidget` (فشل الشبكة ⇒ رسالة قابلة لإعادة المحاولة)، ونموذج الطلب.
- **E2E خفيف بـPlaywright** على 3 مسارات ذهبية: تصفح → إضافة للسلة → إتمام طلب تجريبي.
- **ميزانية أداء في CI**: قياس `web-vitals` على بناء محلي + حد أعلى لحجم `.next/static` (فحص حجم بسيط، بلا مزود).
- **معيار القبول:** `npm test` يشمل الواجهة، ولا يزيد زمن CI عن ~2 دقيقة إضافية.

> ⚠️ **قراري هنا صريح:** لا تُضاف `@testing-library` و`Playwright` تلقائيًا — كلاهما تبعية جديدة تمر ببوابة `npm audit` وتزيد زمن CI، والقرار لك. البنية جاهزة، وبوابة النشر لا تتغير.

### المرحلة 4: تحسين مستمر (بعد استقرار المراحل السابقة)
- كاش الكتالوج: نقل `/` من `force-dynamic` إلى ISR (مثلًا `revalidate = 60`) مع إبطال عند تعديل المنتجات من الإدارة — مكسب زمن استجابة ملموس.
- سجل Web Vitals إلى نقطة داخلية `/api/vitals` (مطابقة لـ`connect-src 'self'`) بدل مزود خارجي ممنوع بالسياسة.
- تقسيم `ChatWidget` إلى مكونات + نقل الأنماط من inline إلى كلاسات (تحضير لأي تشديد CSP مستقبلي يمنع `unsafe-inline`).
- تصميم داكن اختياري عبر متغيرات CSS موجودة أصلًا.

## 5) دليل عملي: كيف تُطوّر واجهة هنا بلا كسر

### إضافة صفحة
```tsx
// src/app/offers/page.tsx
import { getProducts } from "@/lib/db";        // خادمي — مسموح هنا
export const metadata = { title: "العروض — روفيده" };
export default async function OffersPage() {
  const products = await getProducts();
  return <div className="container section">{/* JSX */}</div>;

```

### إضافة مكوّن تفاعلي (بسلام)
```tsx
"use client";
// ✅ مسموح: react، next/navigation، next/link، @/lib/cart، @/lib/shipping، @/lib/seed
// ❌ ممنوع (بوابة CI تفشل): @/lib/auth، @/lib/db، @/lib/orders، @/lib/secrets، @/lib/rate-limit
// البيانات الخادمية تُمرَّر props من Server Component أو تُجلب من /api/*
```
الأنماط: كلاس في `globals.css` مع متغيرات `--green/--gold/--radius` القائمة. تجنّب `style={{...}}` الجديدة — تُضعف أي تشديد CSP مستقبلي.

## 6) توصيات صريحة حول المكتبات (سُئلت عنها ضمناً)

| الخيار | التوصية | السبب |
|---|---|---|
| Tailwind | ❌ لا الآن | 322 سطر CSS منظّم وتصميم مستقر؛ إضافتها = إعادة كتابة كل الأنماط بمكسب صفري في متجر بهذا الحجم |
| مكتبة مكونات (shadcn/MUI) | ❌ لا | ثقل حزمة + لغة تصميم دخيلة على واجهة عربية بسيطة |
