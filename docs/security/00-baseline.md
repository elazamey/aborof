# سجل خط الأساس الأمني (Baseline)

> يُسجَّل هذا الملف قبل بدء تطبيق الضوابط، ويُحدَّث عند كل إغلاق بند حتى تبقى
> المقارنة قبل/بعد قابلة لإعادة التحقق. التاريخ: 2026-09-02.

## القياسات عند خط الأساس

| البند | الحالة عند خط الأساس |
|---|---|
| `npm audit --omit=dev` | `found 0 vulnerabilities` — النسخة المثبّتة في `package-lock.json` (next 16.3.2 / postcss 8.5.23) خالية من ثغرات High/Critical |
| `npm audit` (شامل dev) | `found 0 vulnerabilities` |
| `npm run lint` (ESLint) | ينجح |
| `npx tsc --noEmit` | ينجح |
| `npm run build` | ينجح (5 صفحات + 4 مسارات API) |
| `npm run routes:inventory` | ينجح (10 ملفات مسار) |
| اختبارات الوحدة/التكامل | **لا يوجد** `test` script ولا اختبارات |
| النشر التلقائي | Workflow `Deploy to Vercel` ببوابة lint/typecheck/build فقط، **بدون audit أو اختبارات**، والاختبارات `--if-present` (لا تُفشّي النشر) |

## المخاطر الثمانية كما وردت في التقييم

| الرمز | المجال | الحالة عند خط الأساس |
|---|---|---|
| P0-A | الاعتماديات عالية الخطورة (next/postcss) | الـ lockfile فعليًا على نسخ آمنة؛ يلزم تثبيت `npm audit` كبوابة إلزامية في CI |
| P0-B | تسريب الأخطاء الداخلية | `/api/chat` يعيد `error: String(e.message)` بحالة **HTTP 200**؛ المسارات الأخرى تعيد رسائل عامة فقط ولكن بلا `request_id` |
| P0-C | فصل أسرار الجلسات عن التشخيص | يوجد سر جلسات واحد `ADMIN_SESSION_SECRET`؛ لا توجد نقطة تشخيص، ولكن لا يوجد فصل موثّق ولا حاجز static |
| P1-A | بوابات CI إلزامية | الاختبارات اختيارية (`--if-present`)؛ لا توجد بوابة audit في النشر؛ لا فحص أسرار مطلوبة |
| P1-B | التحقق الموحد من المدخلات | تحقق يدوي موزّع داخل كل مسار (بصياغات مختلفة)، بدون عقود مركزية، بدون رفض حقول غير معروفة |
| P1-C | تحديد معدل موزع | `Map` داخل الذاكرة لكل عملية — يتجاوزه تعدد نسخ Serverless |
| P1-D | سلامة قاعدة البيانات والعزل | الجداول تُنشأ وقت التشغيل عبر DDL؛ لا FK/CHECK/UNIQUE؛ لا هجرات مُرقّمة |
| P2-A | رؤوس HTTP والمراقبة | لا توجد رؤوس أمان؛ لا مقاييس 4xx/5xx/429 |

## قرارات معتمدة للتنفيذ

1. **مخزن تحديد المعدل:** Turso (نفس قاعدة البيانات المُدارة) عبر جدول `rate_limit_counters` مع UPSERT ذري، مع سقوط آمن لذاكرة العملية محليًا فقط.
2. **سياسة كلمة المرور:** 12 حرفًا حدًّا أدنى عند التجهيز/التغيير (موثّقة وقابلة للاختبار).
3. **طبقة المخطط والهجرة:** هجرات SQL مُرقّمة تُدار عبر مشغّل داخلي (`runMigrations`) مع سجل `schema_migrations` و checksum.
4. **سياسة النشر:** لا تخطٍّ لبوابات الجودة على الإنتاج؛ أي فشل في audit/lint/typecheck/security-gates/tests/build يوقف النشر.
5. **بيئة الاختبار:** قاعدة بيانات ملف مؤقتة منفصلة في الاختبارات؛ لا بيانات عملاء.
