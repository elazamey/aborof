## 0) الخلاصة التنفيذية

1. **اليوم الموقع يعمل بـ `wa.me` في 16 موضعًا** (زر فقط، صفر تكلفة، صفر خادم) — وهذا كافٍ وظيفيًا في مرحلة المتجر الحالية.
2. **Elfsight = واجهة تجميلية لنفس `wa.me`**؛ الرسائل تصل إلى تطبيق واتساب العادي، **بلا API وبلا CRM وبلا أتمتة**. قيمته الوحيدة: تخصيص الشكل، والتشغيلات (triggers)، والاستهداف بالصفحة — مقابل **200 مشاهدة/شهر في المجانية** (الودجة تُعطَّل عند تجاوزها) و$5–10/شهر في المدفوعة.
3. **WhatsApp Cloud API = القناة الوحيدة القابلة للربط بـ Celia** (أتمتة، رد آلي، CRM، سجل محادثات) — لكنها تفرض: حساب Meta Business، توثيق النشاط التجاري، رقماً غير مسجَّل على تطبيق واتساب، قوالب معتمدة، ودَفع لكل رسالة.
4. **قرار موصى به:** إبقاء `wa.me` كأساس (P0)، وتحسينه بالقياس والسياق (P1)، والانتقال إلى Cloud API (P2) **فقط** عند وجود سبب تجاري واضح (حجم رسائل، حاجة رد آلي، أو ربط Celia). لا داعي لدفع Elfsight الآن.
5. **تحذير تكلفة عاجل:** «Service messages» — أي ردود البشر أو الذكاء الاصطناعي من طرف ثالث — تتحول إلى **مدفوعة من 2026-10-01** (بعد غد) وفق المصادر الثانوية؛ يُتحقق منها على لوحة الأسعار الرسمية قبل أي ربط آلي.

## 3) التسعير الفعلي — مصر (2026)

**نموذج Meta:** منذ 2025-07-01 صار التسعير **لكل رسالة قالب مُسلَّمة**، بحسب فئة القالب ودولة المستلم — لا لكل محادثة.

| الفئة | السعر/رسالة (USD، مصر) | متى تُحتسب | ملاحظة |
|---|---|---|---|
| Marketing | `$0.0644` | كل تسليم | الأعلى بفارق كبير — حملات ترويجية |
| Utility | `$0.0036` | خارج نافذة الخدمة (ومجاني داخلها حتى 2026-10-01) | تحديثات الطلب، الفواتير، الشحن |
| Authentication | `$0.0036` | OTP وتحقق | خصومات حجم للـ Utility/Auth |
| Service | **مجاني** حتى 2026-10-01 | ردود بشرية/AI على رسالة العميل داخل نافذة 24 ساعة | **يتحول إلى مدفوع 2026-10-01** |
| إضافة | **+14% ضريبة قيمة مضافة** | على الفاتورة المصرية | الأسعار بالدولار، الفاتورة بالدولار + VAT |

**نوافذ مجانية تجب معرفتها:**
- **نافذة 24 ساعة:** ردود غير قالبية مجانية اليوم (تصبح مدفوعة 2026-10-01).
- **نافذة 72 ساعة لـ «Click-to-WhatsApp»:** أي محادثة تبدأ بالضغط على إعلان/زر Click-to-WhatsApp مجانية 72 ساعة.
- **الـ Utility داخل نافذة الخدمة** مجاني حتى 2026-10-01.

**المنصة مقابل المزوّد (BSP):** سعر Meta لكل رسالة **متطابق** عند الجميع؛ الفرق في **رسم المنصة** ووسم المزوّد. الـCloud API المباشر = بلا رسم منصة (تبني الـWebhook بنفسك)، والباقات تبدأ من ~$19–30/شهر لصندوق وارد جاهز. مزوّدون إقليميون (مثل Unifonic) يخدمون مصر. عند المرور بـBSP تُضاف هامش لكل رسالة فوق سعر Meta.

## 4) قيود المستودع التي تحكم الخيارات (ليست تفضيلات)

1. **CSP صارم (`src/lib/security/headers.ts:13`):**
   - `script-src 'self' 'unsafe-inline'` ⟹ **ودجة Elfsight (سكربت من `static.elfsight.com`) لن تعمل** عند تفعيل الإنفاذ.
   - الوضع الحالي **`Report-Only`** (`CSP_ENFORCE` غير مرفوع) — أي أن الودجة قد تعمل الآن **وتُكسر** لحظة تفعيل الإنفاذ.
   - `connect-src 'self' https://generativelanguage.googleapis.com https://api.groq.com https://*.vercel-insights.com` ⟹ Cloud API من المتصفح مستحيل؛ **كل نداءات Graph API تكون من الخادم**.
   - أي ودجة خارجية تتطلب تعديل السياسة + تبرير مكتوب + مراجعة (نمط `docs/security/01-controls.md`).
2. **لا أسرار في الحزمة العميلة:** بوابة `npm run security:bundle` تفحص الحزمة النهائية بحثًا عن أسماء الأسرار. توكن واتساب يجب أن يبقى في وحدة خادم فقط (نمط `src/lib/secrets.ts` و`src/lib/rbac/*` المُقيَّدة بـ`server-only`).
3. **الأعلام fail-closed:** كل ميزة جديدة خلف علم صريح يُقارَن بـ`"true"` حرفيًا (`ENABLE_RBAC`، `ENABLE_CELIA_AGENT`، `ENABLE_MCP_TOOLS`) — وقيمة غير المضبوطة = معطَّل.
4. **الرقم الحالي مسجَّل على تطبيق واتساب** (يُستخدم يدويًا الآن). تسجيله على Cloud API **يُلغي عمله على التطبيق** — أو يُستخدم وضع Coexistence إن توفّر. هذا قرار مالك، لا قرار تقني.
5. **الترحيلات مُقنَّنة:** أي جدول جديد (سجل رسائل، جلسات محادثة) يمرّ بـ`migrations/NNNN_*.sql` + `npm run sync-migrations` + بوابة `--check`.

## 5) القرار المرحلي الموصى به

### P0 — الآن (صفر تكلفة، بلا مخاطر): تحسين `wa.me` القائم
- **نص سياقي لكل نقطة:** مُنفَّذ جزئيًا؛ يُستكمل في الرئيسية والترويسة.
- **وسم المصدر داخل النص** (`?text=… [src:product-42]`) — قياس مجاني بلا تحليلات: يظهر المصدر في أول رسالة يستلمها الموظف.
- **ملف شخصي للرقم** (واتساب Business app مجاني: كتالوج، ساعات عمل، رسالة ترحيب/غياب) — يحسّن التجربة بلا API.
- النتيجة: نفس البنية، مع قياس قناة حقيقي.

### P1 — عند الحاجة لشكل واستهداف بلا خادم: Elfsight **المدفوع**
- **شرط مسبق إلزامي:** إضافة `static.elfsight.com` إلى `script-src`/`connect-src` **مع تفعيل الإنفاذ واختبار التقرير** — وإلا فهو كسر مؤجَّل.
- **لا يُبرَّر في المجانية:** 200 مشاهدة/شهر تُستنفَد في أيام، والودجة تُعطَّل كليًا؛ والمشاهدات تُحتسب لكل تحميل صفحة.
- القيمة الحقيقية: الاستهداف (الصفحة/الجمهور/نيّة الخروج) ورسالة الترحيب — وهما قابلان للبناء محليًا بتكلفة أقل إن صارت الحاجة دائمة.

### P2 — عند وجود سبب تجاري: WhatsApp Cloud API (Meta مباشرة، بلا BSP)
**متى ننتقل؟** عندما يتحقق أحد هذه: (أ) > ~500 رسالة شهريًا تحتاج ردًّا آليًا، (ب) الحاجة لسجل محادثات داخل اللوحة، (ج) ربط Celia بالقناة، (د) تعدد موظفين على رقم واحد.
**لماذا Meta مباشرة؟** نفس سعر الرسالة، بلا رسم منصة، والـWebhook سيُبنى داخل Next.js أصلًا لربط Celia. الـBSP يُبرَّر فقط إذا أردنا **صندوق وارد جاهز** بدل بناء واجهة داخل `/admin`.

## 6) تكامل P2 مع Celia — التصميم الفني المقترح

المبدأ: **إعادة استخدام الطبقات القائمة** لا بناء مسار موازٍ.

```
عميل واتساب ──► Meta Cloud API ──► POST /api/whatsapp/webhook  (Next.js Route Handler)
                                        │
                                        ├─ 1) التحقق من التوقيع  X-Hub-Signature-256 = HMAC-SHA256(body, APP_SECRET)
                                        ├─ 2) idempotency: تجاهل message.id المُعالَج (Meta تُعيد المحاولة)
                                        ├─ 3) العلم ENABLE_WHATSAPP_CHANNEL ≠ "true" ⟹ تجاهل/HMAC
                                        ├─ 4) البحث عن الرقم في جدول المستخدمين/العملاء (قرار: رقم = عميل)
                                        ├─ 5) توجيه النص إلى أدوات Celia عبر الموجود:
                                        │      createCeliaScopeGuard() + celiaAllowedToolNames()  (src/lib/celia/scope-guard.ts)
                                        ├─ 6) تسجيل في سجل التدقيق بنفس نمط RBAC (هوية الفاعل = رقم واتساب)
                                        └─ 7) الرد: POST /{PHONE_NUMBER_ID}/messages
                                               • داخل نافذة 24 ساعة ⟹ رد حرّ
                                               • خارجها ⟹ قالب Utility معتمد فقط
```

**متغيرات البيئة المقترحة (أسماء فقط — القيم لا تُكتب في المستودع أبدًا):**
`ENABLE_WHATSAPP_CHANNEL` (افتراضي `false`) · `WHATSAPP_VERIFY_TOKEN` · `WHATSAPP_APP_SECRET` · `WHATSAPP_ACCESS_TOKEN` (System User دائم) · `WHATSAPP_PHONE_NUMBER_ID`

**ما يجب أن يبقى في وحدة خادم واحدة** (`server-only`) مثل `ADMIN_SESSION_SECRET`، مع بوابة تمنع ظهوره في الحزمة العميلة.

**تعديلات مطلوبة على البوابات عند التنفيذ:** إضافة ملف تكامل واتساب إلى قائمة «خادم فقط»، ومنع أي نداء Graph API من مكونات `"use client"`.

**قرارات مالك مطلوبة (§7) قبل كتابة سطر واحد من P2.**
